# 发布检查清单

发布一个版本之前，照着这张表走一遍：**先自动、再手动**。任何一项打不了勾，就不要发。

```powershell
python packaging\check_release.py     # 自动项一次跑完（版本/产物/哈希/说明）
```

## 一、自动项（`check_release.py` 覆盖）

| 检查 | 为什么 |
|---|---|
| `mihome_pc.VERSION` 能读到 | 版本号是唯一事实来源，打包脚本也从这里读 |
| README 的「当前版本」一致 | 用户第一眼看到的就是它 |
| CHANGELOG 顶部条目一致 | 「每次做好版本更新记录」的最低保证 |
| `docs/04-功能对照.md` 提到当前版本 | 矩阵过时是最容易发生的事 |
| 四件产物齐全（win64 / win32 / deb / tar.gz） | 少一个平台就等于少一批用户 |
| 发布说明存在，且 sha256 与产物一致 | 产物重建过就必须重新生成说明 |

## 二、自动项（其他脚本）

```powershell
python -m unittest discover -s tests   # 全量单测（约 20-25 秒，全部离线）
python -m ruff check .                 # 目标 py38；别显式给路径（会绕过 exclude）
python -m mihome_pc selftest           # 离线自检：目录表/加密/spec 解析
python packaging\verify_deb.py         # deb 结构校验（不依赖 dpkg-deb）
python packaging\verify_distribution.py # 四个产物的许可证与受限数据硬检查
```

## 三、手动项（做完在 PR/发布记录里写一句）

| 检查 | 怎么做 |
|---|---|
| 产物能独立跑 | 解压 portable zip 到临时目录，用包里 `python38\python.exe` 起 `serve --port 18790`，确认 `/api/status` 返回 `demo=true`、首页 200、版本号正确 |
| 界面没坏 | 真账号打开首页 / 设备详情 / 场景 / 消息 / 账号页各看一眼（截图存 `out/`） |
| 新功能真机验证 | 对真实账号操作一遍，并在 CHANGELOG 里写清「改了什么、怎么复原」 |
| 账号没留垃圾 | 测试用的场景/定时/房间/共享全部删除，改过的名字复原 |
| 托盘与快捷方式 | 右下角图标能开界面、右键能退出；安装版桌面有「PC 控制端.lnk」 |
| 绿色版使用须知 | zip 里有 `使用须知.txt`；Linux deb 里有 README |

## 五、不能发的情况

* `check_release.py` 任何一项 ✗ —— 先修，不要「先发了再说」。
* 新功能只在演示数据上验过 —— 真账号没跑通就不算。
* 改了云端数据但没复原 —— 用户家里多了个「测试房间」是很糟糕的体验。
