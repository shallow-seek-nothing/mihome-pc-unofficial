# 外部评审说明（交给 Kimi / 其它评审者）

## 这是什么

一个**米家（Mi Home）PC 客户端**：纯 Python 标准库后端 + 手写 ES5 风格前端，
通过小米云协议读写设备，提供桌面化的网页界面。目标平台 Windows（Win7/10/11），
代码同时保持 Python 3.8 + Chromium 109 兼容。

当前版本 `0.7.26`。需求方明确要求**不做添加设备**（扫码配网留给手机 App）。

## 评审范围（按优先级）

### 1. 安全（最重要）

这是一个**只绑定 127.0.0.1、无鉴权**的本地 HTTP 服务。请重点看：

| 点 | 位置 | 想知道什么 |
|---|---|---|
| 静态文件服务是否可路径穿越 | `mihome_pc/web/server.py` 的静态分支 | `..`、URL 编码、反斜杠、Windows 盘符 |
| 设备 token 是否可能外泄 | `device_info()`、`token` 打码逻辑、日志 | 有没有把完整 token 写进日志/接口/异常 |
| 凭据文件 | `data/credentials.json` 读写、权限 | 是否可被其它用户读；有没有明文落到日志 |
| 子进程调用 | `packaging/build_win.py`、托盘 `mihome_pc/assets/tray.ps1` | 命令拼接是否有注入面 |
| 打包产物 | `packaging/build_deb.py` | tar/zip 写入是否有路径问题 |

### 2. 正确性

* `mihome_pc/domain/` 是纯逻辑（定时 cron 解析、场景 payload 组装、消息归一化、收藏/房间），最容易验，也最值得验。
* `mihome_pc/xiaomi/cloud.py` 是协议层：签名（`sign`/RC4/AES-GCM）、请求组装。可以对照公开的小米协议资料看。
* `mihome_pc/web/server.py` 是路由与 provider（`DemoProvider` / `CloudProvider`）。

### 3. 文档与声明是否诚实

这个项目在 `docs/04-功能对照.md` 里列了 21 项功能矩阵，其中有 3 项标 ⚠️、3 项标 ❌，
并在 `docs/阶段总结.md` 里写明了「做不到的三件事」及其实测错误码。
**请特别检查：文档里声称做到的，代码里真的做了吗？**（这是最容易被自己骗过去的地方）

### 4. 测试

`tests/` 有 474 条 unittest，全部离线。评审时可以跑：

```
python -m unittest discover -s tests     # 需要 Python 3.8+，无第三方依赖
python -m ruff check .                   # 目标 py38
python -m mihome_pc selftest             # 离线自检
```

## 明确不需要评审者判断的事

* **云端协议的具体行为**：需要真实账号才能验证，评审者没有，不要凭直觉断言「这样写不对」。
  如果觉得可疑，请标注「需真机验证」而不是直接判错。
* **Win7 兼容性**：作者没有 Win7 环境，代码按 Chromium 109 / Python 3.8 写，未实机验证。
* **「为什么不做自动化新建 / 房间排序 / 固件升级」**：见 `docs/阶段总结.md`，有实测错误码。

## 已知的取舍（不是疏漏）

* 演示模式（`DemoProvider`）用固定夹具，不联网。
* 未读数靠 45 秒轮询，不是长连接推送。
* 前端不用框架、不用 `?.`/`??`/箭头函数，为的是兼容更老的 Chromium。
* 房间排序、固件升级、设备共享写操作为「不做」，理由已入档。
