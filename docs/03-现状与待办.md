## 1. 怎么跑

```powershell
cd mihome-pc
# 开发态（需要 .toolchain\py38 里的 3.8.10）
& ".\.toolchain\py38\python.exe" -m mihome_pc serve --port 18780

# 首次使用要扫码登录（凭据写进 data/credentials.json）
& ".\.toolchain\py38\python.exe" -m mihome_pc login

# 常用命令
... -m mihome_pc devices                  # 列出设备
... -m mihome_pc view <did>               # 打印控件（spec 驱动）
... -m mihome_pc props <did>              # 读属性
... -m mihome_pc probe <did> --commit     # 矩阵探测可用性（默认只演练）
... -m mihome_pc plugin-sync              # 同步设备插件包并解析文案
... -m mihome_pc selftest                 # 离线自检
```

环境变量：`MIHOME_PC_HOME` 指定数据目录（优先级最高）；否则 `~/.mihome-pc`；再否则 `<安装目录>/data`。
**注意**：本机沙箱下 `~` 可能不可写，开发时建议显式设 `MIHOME_PC_HOME=<项目>\data`。

产物（`dist/`）：`mihome-pc-win64/`（便携目录）、`mihome-pc-0.5.0-portable-win64.zip`、
`mihome-pc_0.5.0_all.deb`、`mihome-pc-0.5.0-linux.tar.gz`。

## 3. 必须知道的协议结论（踩过的坑）

1. **成功码是 `{0, 1}`**，不是只有 0 —— 灯泡族成功写一律返回 `1`；负数才是拒绝（如 `-704220043`）。
   `-704030013` 表示属性不可读。
2. 请求体必须按 **TreeMap 排序**，且 body 顺序要与签名顺序一致。
3. 两种加密：`ENCRYPT-RC4`（key=sessionSecurity，**先烧掉 1024 字节**，body 带 `ssecurity`）与
   `ENCRYPT-AES`（AES-256-GCM，`aes_hash__=base64(iv)`，body 不带 `ssecurity`）。
4. 响应是 `base64(RC4(gzip(json)))`，靠响应头 `MIOT-CONTENT-ENCODING: GZIP` 决定是否解压。
5. `/miotspec/action` 的 `params` 是**对象**，且 `in` 字段即使为空也要给。
6. `/miotspec/prop/get` 返回 `result` 是**列表**；`prop/set` 返回 `{"params":[...]}`。
7. 插件接口 `/v2/plugin/fetch_plugin` 必须用 **`latest_req`/`backup_req` 嵌套体**，扁平体返回全 null。
8. 空的 spec urn 可用 `POST /appgateway/gspec/Gspec/get_instances_by_dids` 补全（`urns:[""]`）。
9. **设备会"接受并忽略"**：写入返回 0 但值没变。判断能不能用必须**写后回读**。
10. 页面状态的等待要看**局域网可达**，别等云端 `isOnline`（后者滞后几十秒）。
11. **设备离线时 `prop/get` 照样返回值**（最后一次上报），`updateTime` 是 Unix 秒；电视实测离线 11 小时仍有值。
    所以「读到值」不等于「设备在线」：`/api/device` 里的 `state_seen` 就是这些值的上报时间，UI 用它标注「12 小时前上报」。

## 4. 待办（按建议优先级）

### P0 · 还没解决的可见缺陷

1. ~~电视属性读不出来~~ —— **0.5.1 已修**。不是协议问题：`prop/get` 对电视正常返回 2.1/4.1/4.2，
   是 `DeviceView.__init__` 把遥控面板的属性从 `controls` 里删掉，`poll_items()` 因此为空，请求根本没发。
   详情与教训见 `docs/reverse/03-真机行为记录.md` §八。离线时用 `state_seen` 把「上次上报时间」显示出来（`12 小时前上报的值`）。
2. ~~Win7 实机验证~~ —— **不在计划内**（2026-11-21 用户决定）：嵌入式 CPython 3.8.10 + 纯标准库 + 保守 JS 已保证
   理论上可跑，不专门找机器验证；等发布到公开仓库后，交给有兴趣的 fork 用户实测反馈。

### P1 · 插件文案已通，但「代码级规则」被证伪（2026-11-21 结论）

* ✅ **文案表彻底打通**：卡点不是偏移解析，是 `string` 类型有 94 个语言分片、后者覆盖前者，
  最后落在 `zh-rTW`，于是 339 条中文全变繁体、按简体 grep 一条也中不了。现在按
  `LOCALE_PREFERENCE`（zh-rCN → zh → default → …）取值：洗衣机 360 条（339 中文）、电视 77 条（59 中文）。
  `plugin-sync` 同时写 `strings.json`（扁平）与 `texts.json`（具名）。
* ❌ **「规则在插件代码里」不成立**：`筒自洁模式下不能预约` 在 584 个 java 里 0 处引用、
  数字 id 0 处、dex 里 `const-string` 引用 0 个方法、407 个资源 XML 里 0 处 `@string/`。
  360 条文案里 212 条被代码引用、148 条没有，而那 148 条**全部**以字面量形式留在 dex 里
  —— 它们是给宿主（主 App 的通用插件框架）按名字解析的，不是插件自己显示的。
  证据与推演见 `docs/reverse/04-插件包下载.md` §10。
* 想拿到「什么状态下允许什么操作」，现实的三条路：
  1. **真机矩阵探测**（`probe --commit` + 写后回读），已有机制、可靠；
  2. 主 APK 的 RN 框架 bundle（`assets/rn_plugins/miot.switch.spec.zip`）里的 enable/disable 判定；
  3. 云端拒绝码（负数 code）建语义表。
* 插件文案的新用途（比规则更实用）：故障码 → 中文解释（`通讯故障（CE）`/`门锁故障（dF）`）、程序名、状态话术。

### P2 · 功能补全

* 局域网日常控制（中枢通道）：mDNS `_miot-central._tcp.` + 双向证书 TLS + `callAPI`，
  协议在 `libcentralclient.so`（2.5MB，mbedTLS）里，需要反汇编。**需一台中枢网关**（用户暂无，已搁置）。
* BLE 直连（不依赖音箱唤醒电视）：`service 6 / ble-control / turn-on`；
  加密原语已定位（`libblecipher.so` 的 `nativeEncrypt`/`nativeMixA`，MAC 逆序 + productId 混钥匙），
  但命令帧格式未知。laptop 已完成广播侧分析（`W:\dsh-mailbox\handoff\ble-scan\`），
  结论：待机时才有 MiBeacon 身份帧（公司 ID `0x038F`），不含开机指令；GATT 枚举失败（BlueZ 走了经典蓝牙）。
* 首页卡片信息量：可加实时值、按房间排序、搜索/收藏。
* 详情页「上一台 / 下一台」导航。

## 6. 环境与坑（省下重新踩的时间）

* **本机没有蓝牙适配器**；电视唤醒靠小爱音箱。ADB 可用：`tools/platform-tools/adb.exe`，
  电视 `<ip>:5555`（**该电视是已改机环境：ADB 常开、`network_wol` 被本会话改为 1**）。
* adb 需要 `TMP`/`TEMP` 指到工作区，否则 `%TEMP%\adb.log` 权限被拒、守护进程起不来。
* jadx 三件套：`JAVA_TOOL_OPTIONS=-Djava.io.tmpdir=<workspace>` + `JADX_CONFIG_DIR` + `JADX_CACHE_DIR`
  （`reverse/tools/jadx.ps1` 已封装）。
* `.ps1` 必须 **UTF-8 带 BOM**；`python -c` 里写三引号补丁在 PowerShell 下会静默截断 ——
  **改用脚本文件**并校验输出（本会话多次踩到）。
* headless Edge 截图在**页面滚动后会拍到全白**，只能验证不滚动的页面。
* 多机协作用共享目录交换笔记（本仓库不含任何主机地址）；
  约定见 `README.md`，交接用 `handoff/`，留言用 `inbox/<from>-<时间>-<slug>.md`。
  laptop 是 **Kubuntu**，别给她发 PowerShell 方案。
* 微信/记忆里的旧结论：`api.mijia.tech` 不可用（返回 `auth error (code 2)`），只用 `api.io.mi.com`。
