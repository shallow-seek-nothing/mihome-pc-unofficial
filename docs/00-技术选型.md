# 米家 PC 客户端 v3 — 技术选型

写于 2026-11-19。依据：`E:\DSH-Archive-2026-11-19\mihome-pc-v2-session\交接给下一个会话.md`
（v2 收尾交接）+ 本轮对 APK `com.xiaomi.smarthome 11.9.705` 的实测。

---

## 0. 结论摘要

| 决策点 | 选定 | 一句话理由 |
|---|---|---|
| 语言 | **Python 3.8**（语法/标准库双限 py38） | 用户硬约束；v2 已验证纯标准库够用 |
| 依赖 | **零第三方依赖**（只用 CPython 标准库） | Win7 上 pip 装东西是灾难；离线可分发 |
| 进程模型 | 单进程：本地 HTTP 服务 + 浏览器 UI | 无原生窗口依赖，Win7/Linux 通吃 |
| UI 技术 | **手写 HTML/CSS/JS**（无框架、无构建步骤） | 不引入 node/build 链；Edge109 直接跑 |
| 独立窗口 | 检测 Chromium 系浏览器并 `--app=` 启动 | 得到"类原生窗口"，零新增依赖 |
| 加密 | 纯 Python `rc4` / `aes`，`hashlib` 做 sha/md5 | v2 实现带单元向量，可直接移植 |
| 协议层 | **独立成库** + 录制 fixture 回归 | 反向出来的协议必须能被测试钉住 |
| 设备 UI 来源 | **APK 提取的型号目录 + MIoT spec 驱动生成** | 不再手写 14 个型号的控件 |
| 可用性规则 | **矩阵探测器生成**（真机跑一遍） | v2 手写规则是最大缺陷来源 |
| Win 分发 | 嵌入式 Python 3.8.10 + `.vbs` 静默启动器 | 用户无需装 Python，双击即用 |
| Linux 分发 | 纯 stdlib + 自带 `build_deb.py`（ar+tar.gz） | v2 已验证；外加 install.sh |

## 1. 硬约束推导出的可行域

### Windows 7 SP1 卡死了什么

| 约束 | 后果 |
|---|---|
| Python ≤ 3.8.10 | 语法封顶 py38；`dict \| dict`、`str.removeprefix`、`zoneinfo`、`graphlib`、PEP585 运行期注解全部禁用 |
| 浏览器 ≤ Edge/Chromium **109** | 可用 ES2020 语法（可选链、`??` 都支持），`replaceAll` 支持；但**不能用** `structuredClone` 以外的更新 API、不能用 WebGPU 等 |
| 没有 WebView2 新版 | 想"内嵌窗口"只能：①Chromium `--app` 模式；②随包带 WebView2 109 Fixed Version（体积+复杂度翻倍） |
| PowerShell 5.1 | 安装/卸载脚本只用 5.1 语法 |
| TLS 1.2 需 KB3140245 或自带 OpenSSL | 嵌入式 Python 自带 OpenSSL 1.1.1，**不依赖系统补丁** —— 这条已解决 |

**结论**：`--app` 模式 + 系统浏览器是唯一"零额外分发体积"的独立窗口方案，选它。
WebView2 Fixed Version 留作可选增强，不进第一版。

### Linux 主流发行版卡死了什么

- 不能依赖 `.so` 编译产物（musl/Alpine、老 glibc 各不同）→ 纯 Python 是唯一稳的。
- 不能用 GTK/Qt 绑定（发行版包名、版本全不一样）→ 同上，网页 UI。
- 服务集成要两套：systemd（Debian/Ubuntu/Fedora/RHEL/Arch/openSUSE）+ OpenRC（Alpine/Gentoo）。

## 2. 候选方案对比（为什么不是别的）

| 方案 | Win7 | 体积 | 工作量 | 判定 |
|---|---|---|---|---|
| **Python 3.8 + 本地网页**（选定） | ✅ | 嵌入式 ~15MB + 代码 ~1MB | 低（v2 已验证） | ✅ |
| Electron | ❌（需 ≤22 且不再维护，打包 100MB+） | 巨大 | 高 | ✗ |
| Tauri | ❌（依赖 WebView2 新版） | 小 | 中 | ✗ |
| C++/Qt5.15 | ⚠️ 可跑但要 VC 运行库 + Qt 插件，Linux 侧要按发行版重编译 | 大 | 很高 | ✗ |
| .NET | ❌ Win7 需 .NET 4.8 且 Linux 侧 Mono/自包含体积大 | 大 | 中 | ✗ |
| Node + 网页 | ⚠️ Win7 上 Node 18 是最后一版，但需装运行时 | 中 | 中 | ✗（Python 已达同样效果且用户指定） |

用户已明确"Python 3.8 上限"，所以不是"要不要 Python"的问题，而是**用 Python 怎么把窗口做出来**——即上一节的选择。

## 3. 选定架构

```
mihome-pc/
├─ mihome_pc/                 ← 发布的零依赖包（py38）
│  ├─ crypto/                 rc4.py  aes.py            纯 Python，带测试向量
│  ├─ xiaomi/                 sign.py  auth.py  cloud.py  miio.py  spec.py  catalog.py
│  ├─ domain/                 model.py  availability.py  engine.py  rules.py
│  ├─ web/                    server.py（stdlib http.server）  api.py  sse.py
│  ├─ assets/                 打包进 pyz 的数据
│  │  ├─ catalog.json         型号目录（APK 提取，12k 型号）
│  │  ├─ specs/               预置 MIoT spec（离线可用）
│  │  └─ ui/                  控件映射 + 可用性矩阵（探测器产出）
│  ├─ config.py  log.py  cli.py  __main__.py
├─ static/                    index.html  app.js  style.css（无框架、无构建）
├─ tests/                     unittest：加密向量 / 签名 / 解码 / spec / 规则 / HTTP
├─ fixtures/                  录制的真实请求响应（脱敏后入库）
├─ tools/                     探测器、spec 抓取、打包、生成 deb
├─ reverse/                   ★ 逆向工作区，**不随产品发布**
└─ docs/                      选型、协议说明、逆向报告
```

### 分层原则

1. **协议层不认识 UI**：`xiaomi/` 只做"说话"，输入输出都是 dict/bytes，可离线单测。
2. **规格层不认识设备**：`domain/model.py` 把 MIoT spec JSON 变成"服务/属性/动作/事件"对象。
3. **UI 层不认识协议**：`web/api.py` 暴露 `/api/devices`、`/api/device/<did>/props` 等，前端只调 REST。
4. **数据与代码分离**：型号目录/spec/控件映射都是 JSON 数据文件，改数据不改代码。

### 与 v2 的关键差异

| 维度 | v2 | v3 |
|---|---|---|
| 型号覆盖面 | 手写 14 个 | APK 目录 12,160 个 + spec 驱动生成 |
| 可用性规则 | 手写，缺洗碗机等 | 探测矩阵生成，带返回码溯源 |
| 协议验证 | 靠真机试 | fixture 回归 + 真机抽验 |
| 逆向 | 无 | 全程记录，产物可复算 |
| Win7 | 未验证 | 第一优先级，从第一天就跑 |

## 4. Python 3.8 约束的落地手段

- **静态卡口**：`ruff check --target-version=py38`，CI/本地一键跑。
- **运行期卡口**：`tests/test_py38_compat.py` 用 `ast` 扫全包，禁止：
  - `ast.BinOp` 对 dict 的 `|`（写起来很难触发，主要靠 ruff）
  - 但更实用的是：用 **真 3.8 解释器**跑一遍 import 冒烟。工具链里下载
    `python-3.8.10-embed-amd64.zip`，`tools/check_py38.ps1` 用它执行
    `python -c "import mihome_pc; ..."`，这是唯一能 100% 兜住的办法。
- **禁用清单**（写进 CONTRIBUTING）：
  `dict | dict`、`str.removeprefix/suffix`、`zoneinfo`、`graphlib`、
  `functools.cache`（3.9）、`list[int]` 形式的运行期注解、
  `asyncio.to_thread`（3.9）、`match` 语句、`int.bit_count`。

标准库白名单（都在 3.8 里）：`base64 binascii hashlib hmac gzip json socket ssl
struct time uuid http.server socketserver urllib.parse urllib.request threading queue
sqlite3 argparse configparser pathlib shutil subprocess sys os re random logging
contextlib dataclasses typing functools itertools collections enum email rfc3339小工具`。

## 5. 交付形态

### Windows 7 SP1 ~ 11（x64）

```
mihome-pc-win64/
├─ python38/            python-3.8.10-embed-amd64 解压产物
│  ├─ python.exe  pythonw.exe  python38.zip  python38._pth  *.pyd  *.dll
├─ mihome_pc/ static/ assets/    （或打包成 mihome.pyz 单文件）
├─ 米家.vbs              双击入口：静默启动 pythonw + 打开窗口
└─ 卸载/更新说明.txt
```

- `.vbs` 内容：`CreateObject("WScript.Shell").Run """python38\pythonw.exe"" _boot.pyw", 0, False`
  —— 无黑框。
- 窗口：`_boot.pyw` 起 HTTP 服务后，按 `msedge.exe → chrome.exe → 默认浏览器` 顺序找，
  找到 Chromium 系就 `--app=http://127.0.0.1:<port>/ --window-size=1100,760`。
- 端口：默认 0（系统分配），写进 `%LOCALAPPDATA%\mihome-pc\port`，避免占用冲突。
  注意：Store 版 Python 的 `%LOCALAPPDATA%` 会被 MSIX 重定向，需要 `sys.executable` 同目录
  的 `data/` 兜底（本机踩过）。
- `.pth` 里加 `mihome_pc` 的父目录即可 `import`。

### Linux

```
./install.sh                # 或  dpkg -i mihome-pc_x.y.z_all.deb
/usr/lib/mihome-pc/         # 代码 + assets
/usr/bin/mihome-pc          # 启动脚本（exec python3 -m mihome_pc）
/usr/share/applications/mihome-pc.desktop
```

- `.deb` 用纯 Python 生成（v2 已跑通 `build_deb.py`：tar.gz → ar 封装）。
- 可选 systemd user unit（跟随登录启动托盘）与 OpenRC 脚本（Alpine）。
- 依赖只声明 `python3 >= 3.8`。

## 6. 逆向与本工程的接口

APK 逆向不是目的，是**规格来源**。三张表落地：

| 逆向产物 | 落到哪里 | 用途 |
|---|---|---|
| 型号目录（12,160 条：model/中文名/品类/卡片类型/连接方式） | `assets/catalog.json` | 设备列表展示、卡片选择、型号识别 |
| MIoT spec 抓取端点与 schema | `xiaomi/spec.py` + `assets/specs/*.json` | 控件自动生成 |
| 可用性/禁用表达式语义（`restrict_expression`、插件 config） | `domain/rules.py` + 探测器 | 解决 v2"操作失败" |

> 逆向工作区固定在 `reverse/`，产物写 `reverse/extract/`，报告写 `docs/reverse/`。
> 任何"从 APK 得到的事实"都要在报告里注明取证位置（类名/资源路径），便于复核。

## 7. 风险与验证清单

| 风险 | 验证手段 |
|---|---|
| Python 3.8 语法漏网 | 用真 3.8 解释器跑全部测试 |
| Win7 上 TLS 1.2 失败 | 在 Win7 SP1 虚拟机实测扫码登录 |
| 浏览器 `--app` 不存在 | 退化为默认浏览器，功能不变 |
| 型号目录过大拖慢启动 | 目录按需切分（品类索引 + 延迟加载） |
| 探测矩阵产生错误规则 | 规则带来源标记（探测/APK/人工），可一键回退 |
| 令牌泄露 | 令牌只写用户目录，权限 600；不进 git、不进日志 |
