## ① 插件文案全设备自动同步，不再需要手动 plugin-sync

**做到**：启动时后台自动拉取每个型号的插件包、解析 `resources.arsc` 文案表并落盘缓存；
界面直接用它翻译枚举值、插件故障码。

**证据**：
- 真账号当前缓存：`minij.washer.v5: 339 条`、`xiaomi.tv.fsv1: 59 条`（`/api/meta` 的 `plugins` 字段）
- 启动日志有 `plugin sync <model> strings=… texts=…`，无插件的型号也会记一行（0 条）
- 语言选择：`arsc.LOCALE_PREFERENCE` 优先 `zh-rCN`，修过 94 种语言「最后一个胜出」导致拿到繁体的问题

```
python -m mihome_pc selftest --env      # 「插件文案：N 个型号已缓存」
```

## ② 对照米家 App 列功能矩阵，逐项补齐

**做到**：`docs/04-功能对照.md` 21 行，15 项 ✅、3 项 ⚠️、3 项 ❌；
每行都写了「还差什么」，⚠️/❌ 的每一项都有**实测证据**说明为什么做不到。

| 状态 | 项 | 说明 |
|---|---|---|
| ✅ | 设备列表 / 控制 / 状态 / 在线判定 / 电视遥控 / 故障码 | spec 驱动，控件自动生成 |
| ✅ | 场景 | 执行、新建（多动作）、编辑、拖拽排序、图标 |
| ✅ | 定时/预约 | 新建、改时间、删除、每周/工作日/节假日、多动作、**下次执行时间** |
| ✅ | 消息/告警 | 列表、类型筛选、全部已读、单条删除、每台设备历史、未读数轮询 |
| ✅ | 家庭与房间 | 房间新建/改名/删除/搬家、家庭改名、收藏置顶 |
| ✅ | 设备信息 | 型号/固件/序列号/IP/MAC/token（打码）/插件文案/最后上报 + 改名 |
| ✅ | 桌面 UI / 托盘 / 安装分发 | 见 ③⑤⑥ |
| ⚠️ | 自动化 | 列表、启停、改名改动作可用；**新建任意触发不可行**（见「做不到」） |
| ⚠️ | 语音 | 只借小爱音箱发「打开电视」 |
| ⚠️ | 设备共享 | 只读成员列表 |
| ❌ | 设备共享写操作 / 固件升级 / 局域网直连 / 多账号 | 接口缺失或风险不对等 |

**做不到的三件事（都有实测证据，不是没做）**：
1. **新建任意触发的自动化**：服务端校验触发里的 `sc_id` 必须对应当前设备的 spec-scene 表。
   手拼、以及原样复制账号里一条真实自动化，都被 `-998 CheckTriggerConditionSrcKey…` 拒；
   该表不在 miot-spec JSON、不在插件包 `package.zip`、也不在 `GetSceneList`。
2. **房间排序**：`ctrroom`/`ctrhome` 没有顺序字段；`set_union_order` 报 `invalid homeid`，
   而 `get_union_order` 返回的 `room_order` 里 id 与真实房间 id 对不上。
3. **固件升级**：OTA 接口未定位，且刷机有变砖风险；只做只读展示，界面标注「升级请用手机 App」。

## ③ UI 按桌面重做，有设计语言，兼容 Chromium 109 与纯标准库后端

**做到**：侧栏导航（全部设备/场景/消息/运行状态/账号与同步）、三列卡片网格、

**兼容性证据（刚跑过）**：

- 前端刻意保守：`?.` 出现 **0 次**、箭头函数 **0 次**（`??` 只在文件头注释里提到「不要用」）
- `ruff --target-version=py38` 全绿；产物内置 Python 3.8.10

```

```
